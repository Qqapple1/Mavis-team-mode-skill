# 可选规则 (Optional Rules)

特定场景下阅读以下规则。不是所有任务都需要这些规则，按需参考。

## 协作规范

适用于多 Agent 协作任务（多个 Worker 同时工作、跨角色依赖等场景）。

### 角色边界
- 不越界做其他角色的事（Coder 不写测试，Tester 不写代码）
- 遇到不确定的问题先问 Leader，不要猜
- 产出文件必须在报告中列出完整路径

### 跨 Agent 沟通
- 通过文件传递信息，不依赖对话记忆
- 遵循 CONTRACT 中定义的接口规范
- 发现其他 Worker 的产出有问题时，通过 Leader 协调，不要直接修改

### 依赖处理
- 尊重 Wave 顺序，不提前读取未完成的产出
- 如果发现依赖的产出有误，标记 `NEEDS-ROLLBACK` 并报告 Leader
- 优先完成自己的任务，不等待其他 Worker

## 会议规范

适用于会议/讨论类任务（技术评审、方案讨论、决策会议等场景）。

### 会议角色
- 主持人（Facilitator）：控制节奏，确保每个议题都有结论
- 记录员（Note-taker）：记录关键决策、待办事项、分歧点
- 参与者：积极发言，但不打断他人

### 会议流程
1. 明确会议目标和议程
2. 每个议题限时讨论
3. 达成共识后记录决策
4. 未达成共识的记录分歧和下一步行动
5. 会后输出会议纪要

### 会议输出格式
```markdown
# 会议纪要

## 议题 1: <标题>
- **讨论要点**: <摘要>
- **决策**: <结论>
- **待办**: <行动项 + 负责人 + 截止日期>

## 议题 2: <标题>
...
```

## 安全底线补充

适用于高 stakes 任务（生产环境部署、对外交付、涉及敏感数据等场景）。

### 额外安全检查
- 所有写操作必须有回滚方案
- 敏感操作（删除、覆盖）前必须确认
- 密钥/凭证不得出现在日志、报告、提交信息中
- 生产环境操作必须有审批流程

### 变更控制
- 重大变更必须有灰度/分批策略
- 变更前必须有备份
- 变更后必须有验证步骤
